## K3a: index.html injection (`32060ae8`)

**Before.** `ScriptInjectionStartupFilter` removed `Accept-Encoding`, `Range` and `If-Range`, buffered the whole response in an unbounded `MemoryStream` and stripped `ETag`/`Last-Modified`. Every app-shell load was therefore a full, uncompressed 200.

Plain Jellyfin 12.4 behaves differently, as a probe of a stock container showed:
- `index.html` is 5,441 bytes and is sent as br by default;
- it carries `Cache-Control: no-cache`, an ETag and Last-Modified, and answers a working 304.

**Design chosen: the plugin compresses, and keeps the source plain.**
- The filter still asks the static handler for the identity file, so it never has to decode a compressed body.
- The injected page is served through the existing `ServedFile` (the bundle's encoder, `ClientScriptBundle.cs`):
  - brotli (q11) or gzip (SmallestSize), chosen by the client's `Accept-Encoding` with `ServedFile.Select`;
  - a strong ETag per representation, a hash of the bytes sent;
  - `Vary: Accept-Encoding`;
  - the source's `Cache-Control` kept;
  - `Last-Modified` dropped, because the script tag can change while `index.html` does not.
- **Why not Canopy's approach** (keep the encoding Jellyfin negotiated, decode, inject, re-encode):
  - Jellyfin's response compression is off for HTTPS by default (the reason the bundle already self-encodes), so in production that approach often has nothing to keep;
  - it needs a decoder for every host encoding;
  - doing the encoding ourselves reuses tested code.

  The page holds no secret and reflects no request input, so compressing it is BREACH-safe.
- **Validators and cache.**
  - Injected pages are cached per shell path (`/web/`, `/web/index.html`, base-url variants), keyed by the source's ETag/Last-Modified and the script tag.
  - A warm request sends the static handler the cached *source* validators. An unchanged file therefore costs a bodyless 304 and no rewrite. The client's own `If-None-Match`/`If-Match` are then evaluated against the injected representation (weak comparison for INM, strong for IM).
  - The client's request headers are restored after the pipeline runs.
  - A changed source answers 200 and replaces the entry; a changed script tag never reuses an old entry.
  - The ETag depends only on the bytes, so a browser's copy still validates after a server restart.
- **Bounds.**
  - The source is captured up to 2 MiB. Past that, the captured bytes and the rest stream through un-injected, and a warning is logged once.
  - At most 4 entries are cached, each at most 512 KiB of identity bytes. In practice that is about 5.6 KB + 1.1 KB + 1.4 KB per entry.
  - A page is never cached if it is incomplete (shorter than its Content-Length, no `</body>`, or the request was aborted) or if it has no source validator.
- **Unchanged:** the injected bytes, the idempotency guard, HEAD/non-GET pass-through, the disable flag, and the downstream-exception path.
- **Not taken from Canopy:** its striped single-flight gates, LRU and full precondition mirroring (the comparison's own advice). Concurrent cold requests each rewrite once, bounded by 2 MiB each.

**Tests** (`tests/backend/Features/Platform/ScriptInjectionCacheTests.cs`, +17):
- **Compression negotiated:** br, gzip, `*`, q-values, identity and none. The static handler never sees `Accept-Encoding`.
- **Per-representation ETags and 304:** 304 has no body and repeats ETag and Vary; weak and list forms; a br tag does not validate gzip; If-Match gives 200 or 412.
- **Warm revalidation:** the source receives its own ETag and Last-Modified and only 1 body is sent for 3 requests; a cold restart still answers 304; a changed source gives 200 with a new ETag.
- **Script-tag change:** the old entry is not reused.
- **Injected content identical:** byte for byte the pre-K3a rewrite, in every encoding, for 5 pages (multibyte, mixed-case and multiple `</body>`, already injected, no `</body>`, a 12.4-shaped shell).
- **Bounded memory:** nothing reaches the real stream below the limit, and from the first write past it every byte has gone through, so at most 2 MiB is held. The cache stays at 4 entries over 12 paths, and the incomplete and validator-less cases are not cached.

`ApiMiddlewareTests` changed in two places:
- the injection test now decodes the gzip body and asserts the new ETag, with no `Last-Modified` or `Accept-Ranges`;
- the "no second tag" test decodes before comparing.

Docs: `docs/advanced/project-structure.md` (what the filter does) and `docs/advanced/api.md` (which responses the plugin compresses).
