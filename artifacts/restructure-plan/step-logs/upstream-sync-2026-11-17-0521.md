## 2. The entry

### 67. The version picker stays on the remembered version when the item page refreshes it

Upstream's `qualitytags.js` restored a remembered version once: on `viewshow` it waited for the picker to fill,
selected the pick and stopped. A refresh of the item that fills the picker again, with no change event, then left the
picker on another version while the poster (which follows the pick) still showed the remembered one. Upstream now
keeps checking for 30 ticks of 300 ms (9 s), reads the pick on every tick and selects it again whenever the picker
shows another version, so a version the user chooses meanwhile is the one it keeps.

The rewrite's `watchVersionPicker` (`client/src/features/media-tags/types/quality/qualitytags.ts`) had upstream's
old logic line for line; it now has the new logic line for line. It still stops on leaving the page and when another
user signs in. No difference from upstream.

Where it shows. Jellyfin 12's web client keeps the picker's current version when it fills it again
(`renderTrackSelections` keeps the current value when the item still has it, since jellyfin-web #7984, in 12.0).
Jellyfin 10.11's selects the first version on every fill, with no change event. So on the Jellyfin 12.4 lab the
picker and the poster already agree after opening the page and after coming back to it, on every build. The fault
shows only when something fills the picker without a change event: Jellyfin 10.11 does that, and so could a theme or
another plugin. The regression test and the lab check both fill the picker the way 10.11 does.
