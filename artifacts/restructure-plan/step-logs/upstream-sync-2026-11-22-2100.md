## 2. The entry

### 111. A home row whose every item is hidden (ported; the rule was already here)

Hiding items hid their cards but left the row around them, so a "Recently Added in <library>" row whose items were all
hidden kept its heading over an empty strip. Upstream adds one rule to the feature's stylesheet:
`.verticalSection:has(.card.je-hidden):not(:has(.card:not(.je-hidden))) { display: none !important; }`, so the row
follows every way a card is hidden or shown again; a browser without `:has()` drops the rule and keeps the old look.

This tree has had that rule, byte for byte and with upstream's comment, since `2beb1e94` (fix(hidden-content), #1096,
landed about 90 minutes before upstream's commit), in `client/src/features/hidden-content/hidden-content.css`, the
stylesheet `hidden-content-styles.js` injects as `je-hidden-content`. So no client source changes. What upstream adds
beyond the rule is ported in `fa6c6204`:

- **Docs.** The sentence "A row whose titles are all hidden is hidden too, heading included." in
  `docs/enhanced/enhanced-features.md` (Hidden Content System), applied as is (`git apply --3way`, clean).
- **Test.** Upstream's test, re-homed beside 2beb1e94's in
  `tests/frontend/features/hidden-content/features-hidden-regressions.test.mjs` (upstream:
  `tests/frontend/features/features-hidden.test.mjs`). 2beb1e94's test covers a direct hide and an unhide; upstream's
  adds the row hidden by `filterNativeCards`, shown again when filtering is turned off, hidden again when it is turned
  on, and shown again when one card is restored. The only difference: the test reaches `getHiddenData`,
  `refreshNativeCardVisibility`, `restoreNativeCardsForIds` and `injectCSS` through `JE.internals.hiddenContent`, where
  this tree keeps them, not `JE.hiddenContent`.

The new test fails with the rule removed from `hidden-content.css` (`every card of the row is hidden, so its heading
must go too`) and passes with it: [`p111.tests.txt`](upstream-sync-evidence/p111.tests.txt).
