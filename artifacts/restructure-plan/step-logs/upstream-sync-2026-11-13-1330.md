What upstream's versions changed since, or added, and `4ccc4428` ports:

1. **An edit refused because the list did not load says so.** A toast, *"Your hidden items could not be loaded, so
   this change was not made. Please reload and retry."* (new string `hidden_content_not_loaded`); hiding asks
   nothing first; a settings panel switch whose change is refused goes back and its side effects (hide buttons,
   the confirmation snooze) do not run.
2. **A save reaches the server's copy of an entry.** Remove from Continue Watching stores the entry under the dashed
   ID while the page mirrors it under the ID it was given. An unhide right after it removed only the page's spelling,
   so the server kept the dashed entry and the item stayed out of Continue Watching. The merge (`model.ts`
   `withChanges`) now applies a change or removal of an entry the page read to other spellings of its key the page
   never read; keys the page read and left alone stay.
3. **A save with nothing of the page's own to write posts nothing** (a hide undone before its save, say).
4. **Each request of a save fails after 30 seconds**, so a save that gets no answer is retried instead of holding
   later saves and a Continue Watching / Next Up removal; the removal is refused with its message, since the write
   may still land.
5. **Names older Seerr cards stored HTML-escaped are no longer rewritten by a save of other changes.** They still read
   as the title (`withPlainNames`); a save merges onto the list as stored.
6. **`refresh()` keeps changes not saved yet** on top of the list it reads.
7. **The page says whether it showed** (`showPage()` returns it) and the Manage button uses that, so Plugin Pages
   chosen but not installed opens the page again (`92286fb2` opened the dialog there).
8. **Server: content that does not parse is set aside once.** GET `hidden-content.json`, GET `shortcuts.json` and
   the bootstrap move it to `.corrupt-<ts>`, as a save does, so the next read is the defaults instead of a failure on
   every page load; `3d6c27f1` left it in place. Upstream reads again under the file's lock before moving it and
   makes the shortcuts save take that lock. Here the strict read already holds the lock for the read and the move,
   leaves a file it could not open where it is, and every save takes the lock, so the change is to let those three
   reads set content aside. The 500 messages are upstream's.
9. **Docs.** `docs/enhanced/enhanced-features.md` and `docs/advanced/api.md` take upstream's hunks (`git apply`,
   clean), with the bootstrap lines saying *null*, as this tree's bootstrap writes it. The coverage-matrix row names
   this tree's tests.
