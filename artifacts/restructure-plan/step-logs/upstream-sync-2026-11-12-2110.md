## 2. The port

### 33. The playback info shortcut opens Jellyfin's own stats panel (`d6d454be`, `Upstream: c55c758ede4a0f26192196ec8a9328dd9bc695cc`)

Until now the Show Playback Info shortcut (<kbd>I</kbd>) toggled only JE's own statistics overlay, in upstream and
here. Upstream now first opens jellyfin-web's native stats panel: it clicks the player's settings button while a
style keeps every dialog invisible, waits up to 1.5 s for the menu's "Playback Info" entry (`data-id="stats"`),
clicks it, and removes the style 400 ms later. Without the button or the entry, or when that throws, the plugin
overlay opens as before.

| Upstream | Here | How |
|---|---|---|
| `js/enhanced/player/playback.js`: `toggleNativePlaybackInfo`, `JE.togglePlaybackInfo` async with the fallback | `client/src/features/player/playback-info.ts` | re-implemented |
| (its own `requestAnimationFrame` wait, plain `.click()`s, its own sheet close) | `client/src/features/player/native-track-menu.ts` | the track menus' `openOsdMenu`, `activate`, `closeActionSheet` are returned by `createTrackMenu` and reused; `openOsdMenu` takes its timeout |
| `js/enhanced/events.js`: a comment | `client/src/features/chrome/events.ts` | the comment; `player/host.ts`: the function's type is `Promise<void>` |
| no docs change | `docs/enhanced/enhanced-features.md` | the shortcut's two descriptions |
| no test | `tests/frontend/features/player/features-playback-info.test.mjs` | six tests |

Differences from upstream:

1. **The menu is driven the way the track menus already drive it.** The new sheet is awaited with
   `JE.core.dom.waitForElement` (scoped to a container that did not exist before the click) instead of a
   `requestAnimationFrame` loop, and the button and the entry get a `pointerdown` before the click. In Firefox,
   jellyfin-web's video OSD drops a click whose target does not contain the target of the last keydown or
   pointerdown (the comment on `activate` in `native-track-menu.ts`). After the key press that is the page body,
   so upstream's plain `.click()` never opens the menu there: upstream's build shows the plugin overlay after its
   1.5 s wait in Firefox; the port opens the native panel (section 3).
2. **A menu without the entry is closed for real.** Upstream clicks a `.dialogBackdrop` inside the sheet's
   `.dialogContainer`. jellyfin-web 12.4 puts the backdrop before the container, not inside it, and closes a sheet
   only for a click on the container whose mousedown landed there too (`p33-sheet-dom`: a lone click on the
   container or on the backdrop leaves it open; mousedown and click close it). So upstream's sheet stays open,
   invisible for 400 ms and then visible beside the plugin overlay, also after the overlay is closed again. The
   port closes it with `closeActionSheet` (pointerdown, mousedown and click on the container), unseen.
3. **One attempt at a time.** A second press while the menu is still opening is ignored. Upstream starts a second
   attempt; in Firefox, where each attempt waits the full 1.5 s, a second press during the wait left two plugin
   overlays on the lab, the first no longer referenced and never removed. When the player is left while the menu
   opens, the wait ends with the player's lifetime and the press's lease is checked, so no overlay follows. The
   hiding style is removed by a plain timer, not one of the player lifetime's, so a navigation cannot cancel its
   removal and leave every dialog invisible.
4. **Docs**: `docs/enhanced/enhanced-features.md` says what the shortcut does now. Upstream's still says it toggles
   JE's overlay.

Differences 1 to 4 are filed as one found bug of upstream's
(`NEW-20261112-213650-upstream-c55c758e-the-playback-info-shortcut-lea`).

Kept from upstream as it is: the 1.5 s budget and the 400 ms hiding style; the warning text when the attempt
throws; jellyfin-web's own page error "ActionSheet closed without resolving" when the fallback closes the menu
(the same error a person's click beside any sheet causes; seen on the lab with a real pointer click too); a menu
that opens only after the 1.5 s is not closed.

The guessed class and features (`feature`, `chrome` and `player`) were right: the behaviour is the player's, and
chrome's shortcut table only gets a comment.

## 5. Risk, for the reviewer

- **Something outlives the page.** The port injects a `<style>` that makes every `.dialogContainer`,
  `.dialogBackdrop` and `.actionSheet` transparent. It is removed 400 ms after each attempt by a plain
  `window.setTimeout`, which a navigation does not cancel (the test "leaving the player" checks it). Nothing else
  is added: no listener, observer or interval; the wait is the shared `waitForElement` with the player lifetime's
  signal.

- **Requests to other hosts.** None. The native panel is jellyfin-web's own; no request is added (the lab runs'
  `BLOCKED` lines are the same on all three builds: three in Chromium, two in Firefox).
- **Access, privacy, spoilers, stored data.** None touched. Nothing is stored; no setting is added.
- **Routes, authorization, registrations:** none changed.
