## 2. The entry

### 42. Streaming providers from Seerr when there is no TMDB key (#1058, fixes #1052)

What upstream does: with no TMDB key and the Seerr integration on, the Elsewhere panel, the Seerr poster icons
and the More Info streaming row read Seerr's own watch-provider data, and the watch-providers batch endpoint falls
back to each title's Seerr detail. A new admin option, "Use each user's Seerr streaming region" (off), looks
providers up in each user's Seerr streaming region (their own, else Seerr's global one, else US) for the Elsewhere
panel and search, the poster icons, the More Info row and the discovery filters, read through a new route
`GET jellyseerr/streaming-region`. Per-season providers stay TMDB-only. `status-tags/trending` answers `no-store`.

**Why it is deferred.** The batch fallback goes through `ProxyJellyseerrRequest`, as upstream's does, so its auth
reads count for `GetWatchProvidersBatch`. Two existing contract lines change
([`p42-contract-tests.txt`](upstream-sync-evidence/p42-contract-tests.txt)):

- `auth-helper-calls.snapshot.json`, `GetWatchProvidersBatch`, and `auth-reads-by-route.base.json`,
  `GET JellyfinEnhanced/watch-providers`: `{"User":1,"UserHelper.GetCurrentUserId":1}` becomes
  `{"IsAdminUser":5,"User":2,"UserHelper.GetCurrentUserId":2}`.

An unattended run lands only added contract lines; a changed one is left for the maintainer. Keeping the old
lines would mean reading Seerr outside the proxy, without its permission checks, parental gating and response
cache, which is a weaker check than upstream's, so the port keeps upstream's path and waits for review. The rest of
the contract change is additions only: the route `GET jellyseerr/streaming-region` (`[Authorize]`, no
parameters, reads the caller once) in `route-auth.snapshot.json`, `auth-helper-calls.snapshot.json`,
`auth-reads-by-route.base.json` and `baselines/inventory-routes.txt`, and `ExpectedRoutes` 206 → 207. No DI
registration changes.

What the port does differently from upstream (the side branch's ledger entry has the full list):

- The Seerr streaming region belongs to the signed-in user everywhere: a user switch clears it and an answer for a
  user who has left is dropped. Upstream's poster icons keep their own copy of the region request that a switch
  never clears, so after an SPA switch the next user's icons follow the previous user's region; here the icons read
  the Seerr API's region. Filed as a found bug.
- When the region arrives after the Elsewhere panel was drawn, the panel is rebuilt if the country changed; upstream
  leaves the panel in the old country until the next page. Filed as a found bug.
- Seerr's `watchProviders` are read into the TMDB shape with `link` and `flatrate` only (what the panel reads).
- `createAutocompleteInput` moved unchanged from `elsewhere.ts` to `elsewhere-autocomplete.ts`, so `elsewhere.ts`
  stays inside its size ratchet; its `size-baseline.json` entry falls from 1,103 to 970.
- Docs as upstream; `api.md`'s route count goes from 206 to 207 here.
