## 2. The entry

### 98. Configuration page: analytics icons, sidebar links, search

What upstream changed, all on the configuration page:

- **Analytics icons.** Right after a reload the first `GET usage/fields` can fail before the session is ready, which
  left the page without its insights icons. The page now tries once more two seconds later, and the engine keeps the
  list and draws the icons again on every refresh, so a card drawn or filled after the list arrived still gets them.
- **Sidebar.** The link to a group inside a card (the sidebar's third level) is hidden while the card hides that group:
  a showIf condition that is false, or the card's main switch off.
- **Settings search.** It runs 300 ms after the last keystroke (was 150) and only from 3 characters (was 2, with the
  hint now "Type 3+ characters to search"): two letters such as "re" highlighted over a thousand matches and froze
  typing.
- **Stylesheet.** `.jea-nav-leaf[hidden]` stays hidden (the links are `display: block`), cards keep a 20 px gap in
  search mode, and under 600 px a New badge wraps onto its own line above the setting's text instead of squeezing it.

How it was ported. The client is re-implemented in `client/src/admin/config`: `engine/index.ts` (the kept list and
`applyAnalytics`, run from `refresh`), `engine/shell.ts` (`syncTree`, run from `refresh` after `syncShowIf`, the
same rule as upstream), `page/load.ts` (one retry) and `page/search.ts` (300 ms, 3 characters). Upstream's
`jeAdmin.css` hunk applied as is. Differences from upstream, all in the entry's `notes`: the retry runs on the page
lifecycle's timer, so it is dropped when the page goes away; an answer that is not a list is not retried (upstream's
`new Set({})` throws and so retries an object answer); the link's group is kept in a `WeakMap` rather than an expando
property; `markAnalytics` keeps its typed list argument. Upstream's choice to start the search at 3 characters means
short names such as "tv" or "4k" no longer search; that is ported as is.

Tests. Six new tests, each recorded failing on the tree before the port and passing on `be993510`:
`tests/frontend/admin/config/admin-config-sidebar-search.test.mjs` (group links follow a main switch; group links
follow a showIf condition while the card's other links stay; the search starts at 3 characters, 300 ms after the last
keystroke; the stylesheet rules) and two in `admin-config-address.test.mjs` (a failed read is tried once more and its
answer draws the icons, never a third read; the kept list draws a lost icon again on the card's next change). The Media
Tags tab tests that type into the settings search waited for the 150 ms debounce plus a margin; they now wait for
`SEARCH_DEBOUNCE` (300) plus the same margins, with their assertions unchanged (with the old waits "searching and
clearing the search leaves the Media Tags tab as it was" no longer sees search mode).
