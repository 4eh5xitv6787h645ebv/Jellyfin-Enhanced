### 39. fix(seerr): Seerr routes follow the caller's library access and Jellyfin's parental rules (#1055)

Upstream squashes the seven commits of its PR. Their first versions landed here on 11–12 November, as the rewrite's
own commits, and are not repeated:

| Upstream's part | Here first |
|---|---|
| studio/, genre/, boxset/ and items/by-providers resolve the item through the caller | `fc27dc69` |
| person/ through the same check | `63e5d7ef`, `c2197790` (auth-read lines `bc86d499`) |
| the certification falls back to the US one, and for a series the first listed; scored in the server's country | `a1786432` |
| a sub-score limit decides only at its own score | `989f3c0b` |

Upstream's versions changed four things since, and those are what `7d96b61d` ports. The diff was read file by
file against this tree (indentation, namespaces and the controller split aside):

1. **Studios, genres and persons are answered to any signed-in caller.** Jellyfin's user item overload
   (`GetItemById<T>(id, user)`) hides an untagged studio or genre (and on 10.11 a person) from a user with an
   Allowed Tags list, while Jellyfin's own `/Studios/{name}`, `/Genres/{name}` and `/Persons/{name}` routes answer
   them. Here the caller check took the studio and genre discovery rows away from such a user. `GetItemForCaller`
   is now upstream's (`Features/Seerr/JeSeerrController.Discover.cs`): titles and box sets still go through the
   caller.
2. **A series' certification is picked as Jellyfin's TmdbSeriesProvider picks it.** The country's first entry,
   else the first US entry, else the first listed, and the entry picked decides: an empty rating there leaves the
   title unrated (Jellyfin stores a bare country prefix that no rating table knows). `a1786432` tried every country
   and US entry and skipped empty ones, so a series rated `""` in Germany and `TV-MA` in the US was refused on the
   Seerr pages while the library treats it as unrated (or the other way round for a user who blocks unrated
   series). An entry with no rating at all is passed over, as Jellyfin 12 does
   (`Shared/Parental/SeerrCertificationExtractor.cs`).
3. **items/by-providers checks at most the first 100 matches** for a non-administrator
   (`Features/Calendar/JeCalendarController.cs`), so an untyped lookup of an id stamped on many episodes does not load
   each one.
4. **Comments and docs.** The override-rule comment no longer says Seerr does not gate that route
   (`JeSeerrController.cs`); the extractor's and the filter's comments describe the pick. `docs/advanced/api.md` and
   `docs/seerr/seerr-features.md` take upstream's hunks as is (`git apply`, clean, offset 6 lines);
   `tests/docs/coverage-matrix.md` takes upstream's two sentences with this tree's test file names.

Not ported: the rewrite builds for Jellyfin 12 only (`JellyfinEnhanced.csproj` refuses any other target), so
upstream's `#else` branch for 10.11 in `ExtractTv` and in its no-rating test has nothing to run on here. The test
keeps the Jellyfin 12 assertion, under the name `ASeriesWhoseLocalEntryHasNoRatingMovesOnLikeJellyfin12`.

Risk: change 1 answers more for by-name entities only, and only what Jellyfin's own routes already answer to the
same caller; titles and box sets are still checked, and administrators are unchanged. Change 2 makes the Seerr
verdict equal the library's in the cases where they differed, in both directions. Neither stores anything.

Tests: upstream's `ItemLookupAccessTests` is split here by controller, as `fc27dc69` and `63e5d7ef` split it; its two
new by-name tests are `ApiItemInfoAccessTests.AStudioOrGenreIsNamedForAnySignedInCallerAsJellyfinsOwnRoutesDo` and
`ApiPersonInfoAccessTests.APersonIsNamedForAnySignedInCallerAsJellyfinsOwnRouteAndPeopleInfoDo`.
`ApiItemByProvidersAccessTests.ALookupOfAnIdOnManyItemsChecksAtMostTheFirstHundred` is this tree's own (upstream
has no test for the bound). `SeerrParentalCertificationTests`, `ApiSeerrTests` and `PrivacyPolicyTests` get the
cases upstream added (listed in the ledger's notes).
