## 5. Risk, for the reviewer

- **Access, privacy, spoilers.** Port 20 adds one fact a user can receive: the newest added date among a collection's
  members. On the cache path it is dropped for a user who cannot see the member it came from (the existing per-user
  filter, upstream's test); on the `/tag-data` path it is computed from the members Jellyfin returns for that user
  (the added test: a second user gets the older member's date, never the hidden one's). No check is loosened.
- **Stored data.** The tag cache schema moves from 10 to 52: on first start the server discards its snapshot and
  rebuilds it, and each browser drops its stored copy and downloads a full one. The resolver version moves, so native
  poster addresses change once and posters are drawn again. Nothing a user saved is touched.
- **Routes, authorization, registrations:** none changed. **Requests to other hosts:** none added. The admin search
  asks the Jellyfin server for the Media Tags scripts and the plugin configuration the first time it is used.
- **New setting:** `StatusTagsOnCollections`, default on (behaviour as before until an administrator turns it off).
  Since port 20, "on" means a collection is badged by its newest member, so a collection that was only badged
  because a tool had just recreated it loses its badge. That is the fix.
- Undo: `git revert 87c0ac03 b05533b3 2dfd3530` (and the ledger commit). After a revert the cache schema is 10
  again and the snapshot is rebuilt once more; stored settings need nothing (the unknown property is ignored).
