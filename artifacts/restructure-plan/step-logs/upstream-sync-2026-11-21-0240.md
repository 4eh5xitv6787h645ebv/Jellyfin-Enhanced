## 2. The entry

### 97. Reclaimerr through its 0.6.15 token API

What upstream changed. One squash of about twenty commits. The Reclaimerr integration now needs Reclaimerr 0.6.15 or
newer (development builds count as the release they lead up to) and talks to it with the API token alone: Leaving soon
reads `/api/v1/leaving-soon` and matches entries by the Jellyfin item ids Reclaimerr lists; mark, keep and postpone use
the token's scheduled-deletion and candidate endpoints and pick a movie version by media source id; requests are listed,
approved and denied with the token, and a user's own request is filed as the Reclaimerr account linked to their Jellyfin
user id through Reclaimerr's trusted-proxy sign-in. The service account (username, password, cookie login and the Create
service account button), the Jellyfin-to-Reclaimerr user map and the act-as-user switch are removed; "Create accounts for
Jellyfin users" becomes "Import Jellyfin users" (Reclaimerr's own import); a read-only user audit is added. The squash
also carries fixes written over the token API: no leave date on an approved request whose schedule was kept or has run, a
merged movie listed once, standalone visibility for request cards and the request gate, a 30-second request-list cache
shared by all callers with a generation counter, and the administrator told why requests could not load.

Why it is deferred. A port changes the frozen contract, which this unattended run may not do (additions only, in a
separate commit). It **removes** two existing routes and their lines:

- `POST JellyfinEnhanced/reclaimerr/service-account` (`CreateReclaimerrServiceAccount`)
- `POST JellyfinEnhanced/reclaimerr/create-users` (`CreateReclaimerrUsers`)

from `tests/backend/Architecture/route-auth.snapshot.json`, `auth-helper-calls.snapshot.json`,
`auth-reads-by-route.base.json` and `artifacts/restructure-plan/baselines/inventory-routes.txt`, and **adds** two
administrator-only routes, `POST reclaimerr/import-users` and `GET reclaimerr/user-audit`. It also removes four stored
settings (`ReclaimerrUsername`, `ReclaimerrPassword`, `ReclaimerrUserMap`, `ReclaimerrActAsUser`) for a new
`ReclaimerrUserRequests` that is off by default. The fixes in the squash depend on the token API (the list's shape, the
request rows, the cache), so the commit is left whole rather than split by guesswork. Nothing of it is ported.

What a maintainer has to decide (the entry's `needs`): accept removing the two routes' lines and adding the two new
routes, after which a later run ports the whole commit with those snapshot changes in its last commit for review; or
keep the two routes (and say how they behave without a service account) and port the rest with only the two additions.
