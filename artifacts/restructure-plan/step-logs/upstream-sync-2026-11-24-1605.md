### 113. TV remote navigation (ported)

The shared helpers go where upstream put them, on `JE.core.ui` (`client/src/core/ui/runtime.ts`): `isTvBackKey`,
`swallowTvBack` (Back presses within 500 ms of a window closing, and a held key's repeats, are swallowed so they close
neither the next level nor, on Home, the app) and `rememberFocus`. The window listener goes through the UI host, which
returns its remover (the leak guard requires a removable global listener). The key test is also a pure module,
`core/ui/tv-back.ts`, that the features import. With these, Back closes More Info, the request window and a
key-opened Seerr card overview; the request window is a `focuscontainer`; focus returns to the opener on TV; More
Info's external links are inert on TV; the header tab strip no longer covers the random button from 100em.

Two of upstream's test assertions differ here, both for reasons in the rewrite's code: the request window closes on
Back itself rather than on `popstate`, so the held-Back test checks that a later Back is no longer swallowed instead of
counting a second pop; and More Info shows 5 external links where upstream shows 6, because upstream also draws a
Rotten Tomatoes fact with an empty href when a title has no Rotten Tomatoes page.

Lab, TV layout (`p113-tv-remote.mjs`): before the port Back left More Info and the request window open, the links
opened new windows and the tab strip was 1056px wide; on upstream's build and on this branch alike Back closes both
windows, a second Back at once is swallowed, focus returns to the random button, the links are inert and the strip is
559px.

### 114. CSS and API fallbacks for older TV engines (ported)

A `replaceChildren` polyfill installed first in `plugin.js` (`client/src/bootstrap/loader/polyfills.ts`);
`Intl.DisplayNames` feature-detected at upstream's three places; the Home backdrop target queried without `:is()`;
`.layout-tv … :focus` twins of the `:focus-visible` rules for the launcher, the pause screen's close button and the
Seerr season, collection and TVDB-match rows; a plain 360px height before More Info's `clamp()`. Three tests fail
without the port and pass with it (upstream's language test, plus new ones for the polyfill and for a `querySelector`
that rejects `:is()`). The lab's Chromium has all of these APIs, so nothing changes there: the native `replaceChildren`
stays (`p114-native-apis.after.txt`) and the smoke passes. Other `querySelector` calls with `:is()` remain in the
rewrite, as in upstream: filed as a found bug (section 4).

### 115. Custom elements created with their type (ported)

On engines with native v0 custom elements an `is` set after creation is never upgraded. One typed helper,
`createCustomElement(tag, type)` in `client/src/features/shared/dom.ts`, calls `document.createElement(tag, type)` (the
form jellyfin-web uses) and sets `is` itself where nothing handled the type; all 40 places that set `is` after
creating an element use it, with upstream's per-place choice of `classList.add` over assigning `className`. Upstream has
no test; new tests emulate a v0 engine for the shared external link and the Home tab button, check that the markup is
unchanged where nothing handles the type, and check that no client source sets `is` after creation. Lab
(`p115-custom-elements.mjs`, desktop and TV): every JE element with an `is` reads the same on upstream's build, on this
branch and on the main line before, which is the expected result on a modern engine.

### 116. One remote stop per card, OK opens the title on TV (ported)

`client/src/features/seerr/core/ui/cards.ts` as upstream: the card batch knows the TV layout; with More Info loaded the
title link has `tabindex -1` and OK on the poster opens the Jellyfin item, the collection's request window or More
Info. Upstream's test change applied as is. Lab (search "Mock"): before, OK opened the overview and Back left the page;
on upstream's build and on this branch OK opens More Info and Back closes it with focus back on the poster.
