## 2. The entry

### 93. Leaving soon: request-style cards, sizes, sturdier Reclaimerr requests

What upstream changed. The Leaving soon page's leaving cards and request cards take the Requests page's layout (poster
left, details right, one column on a phone) with theme-neutral greys. A leaving card shows the day it leaves ("Leaves on
24 Nov 2026") and what leaving frees: a movie's file, a series' episode files, or for one version of a movie the size of
the version Reclaimerr names (a scheduled deletion's estimate, or the candidate's version through the service account,
kept for 30 minutes). Request dates read like the Requests page ("3d ago", then "23 Nov 2026"). A request shows what it
would delete (a season, an episode, one version); the approve confirm names that scope and takes a note; approved
requests whose deletion failed or waits for playback stay listed; the list answer says when the requests could not be
read in time (`requestsUnavailable`); title lookups run once per title, in parallel; a user's own requests from the
service account's list are only rows the service account filed; a review the service account sends names the
administrator in the note.

Here. Upstream's `Services/ReclaimerrActions.cs` hunk applies as is to `Features/MediaTags/Services/ReclaimerrActions.cs`.
Its `LeavingSoonController` changes are re-done in the feature's partial `JeMediaTagsController.LeavingSoon.cs`, the DTO
in `Features/MediaTags/Models/ReclaimerrRequests.cs`. The page is `client/src/features/media-tags/leaving-soon/
leaving-soon-page.ts`; its stylesheet `leaving-soon-page.css` was byte-identical to upstream's old one and is upstream's
new one byte for byte. The nine English strings are upstream's.

Four differences, each with a test that fails on upstream's version (and each filed as a found bug against upstream):

1. **The review note names the administrator whenever the service account actually sends the review.** Upstream decides
   before sending, from whether a Reclaimerr account is found; when Reclaimerr then refuses the mapped administrator and
   the service account steps in, the review went out anonymous. Here `SessionAsync` takes the attributed body as
   `serviceBody`, used only by the service-account call. Upstream's logic run against the new test:
   `Expected ("svc", "gone (Approved by Admin in Jellyfin)"), Actual ("svc", "gone")` (`p93.tests.txt`, on `@5f3df788`).
2. **A requester reads the administrator's note.** Upstream hides every note ending " in Jellyfin" or " in Jellyfin)",
   which is every note carrying the server's "(Approved by NAME in Jellyfin)", so a note typed in the new confirm never
   reached the requester when the service account filed the review. Here only that suffix (or a note that is only the
   attribution) is removed.
3. **A request poster takes a full address only on `https://image.tmdb.org/`.** Upstream uses any http(s) address
   Reclaimerr names, which can be a host the browser never asked before (REVIEW.md 1). A path keeps the w185 TMDB URL as
   before; anything else draws the fallback icon.
4. **A title lookup that runs out of the 8-second budget only costs its card the Jellyfin link.** Upstream's commit says
   so, but its lookups catch a cancellation only when the budget's own token is not cancelled, so an expired budget
   still dropped every request already read. Here the lookups run under the budget and a cancellation by it (the
   request itself still live) gives no link. The budget is `ReclaimerrActions.ListBudget` (8 s; tests set it, as they
   set its `Timeout`).

Tests. Upstream's three files at this tree's folders: `tests/backend/Features/MediaTags/PosterTags/ReclaimerrRequestRowTests.cs`,
`tests/backend/Features/MediaTags/IntegrationReclaimerrVersionSizeTests.cs` (which also disposes the tag caches it
creates) and `tests/frontend/features/media-tags/features-leavingsoon-request-cards.test.mjs` (over `tags/tag-item-menu.js`,
where the page ships), plus upstream's change to the row-names test in `LeavingSoonTests`. Added here: four route-level
tests in `IntegrationReclaimerrActionsTests` against the loopback Reclaimerr (failed and held-back approved requests with
their scope, and only the service account's rows for a user; the review note; the sizes; the budget, for which the
loopback server now answers a delayed request on its own), two client tests for differences 2 and 3. Each new test was
recorded failing on the tree before the port (the four route tests on assertions, with the two upstream test files that
cannot compile before it set aside for that run), and passing on `93e90c96`. Two existing tests change with the
behaviour: the one-version card test reads the new badge and the year beside the title, and the translation-coverage
test lists the Requests page's four "ago" strings as shared strings, which the page now uses as upstream's does.
