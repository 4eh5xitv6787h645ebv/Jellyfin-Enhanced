## 2. The port

### 30. Plays and favorites of versions, people and genres (`6493469c`, `Upstream: c693f0eddbd2fc26df25ac53dbd197a8fbffb0f7`)

Jellyfin 12 hides an alternate version of a movie or episode from every user query, so an Activity Feed entry
stored against a version's id never passed the feed's access query, not even for the person who played it. A
favorited person, genre, studio or music artist or genre has no library, so it never passed either. Upstream now
resolves both when the feed is read (its issue #1013).

| Upstream | Here | How |
|---|---|---|
| `Services/ActivityFeedBuilder.cs` | `Features/Activity/Services/ActivityFeedBuilder.cs` | upstream's Jellyfin 12 code as it is |
| `tests/backend/Privacy/ActivityFeedHiddenItemsTests.cs` | `tests/backend/Features/Activity/ActivityFeedHiddenItemsTests.cs` | its ten Jellyfin 12 tests, at the moved path and namespace |
| `docs/advanced/api.md`, `docs/enhanced/enhanced-features.md` | the same two pages | the two paragraphs, without the 10.11 wording |

The C# file was moved, not rewritten. Before this commit the rewrite's file was upstream's with its Jellyfin 12
branches taken: upstream's file at `c693f0ed^`, with the `#if` lines and the 10.11 branches removed and the two
moved names (`Infrastructure.Extensions`, the namespace), is byte-identical to the rewrite's at `1a68c68a`. So
the port is the same operation on upstream's file at `c693f0ed`. What it brings:

- `PermittedIds`: the feed's access query (the viewer's own scope from `ConfigureUserAccess`, then the ids), now
  with `GroupByPresentationUniqueKey` off, because a user query keeps one id per title and every version shares
  its title's key.
- `ResolveHiddenVersions`: an id the page query denied is shown as its primary version (or owner) when the version
  passes the same query with Jellyfin's `IncludeOwnedItems`, and the title passes the ordinary query.
- `PermittedByNameIds`: for favorites only, the query names the five by-name kinds in `IncludeItemTypes`, which
  makes Jellyfin apply its by-name rule. An item with a `ParentId` (a music artist that is a folder of a library)
  stays under the library rule.
- One `Watched` and one `Favorited` row per person and title: the newest row, with the highest progress and any
  completion. `MergeLaterVersionPlays` does the same for watches past the page that filled the feed, so a row
  does not depend on the limit.
- A failing version or by-name lookup hides those rows and logs a warning; the ordinary rows still load.

Differences from upstream:

1. **Jellyfin 12 only.** This tree has no 10.11 build, so upstream's `#if !JF12` lines (the 10.11 query and its
   two empty lookups) and its one 10.11 test (`OnJellyfin1011TheFeedKeepsItsOneLibraryQueryAndByNameFavoritesStayHidden`)
   are left out. Nothing else differs in the code.
2. **Tests** live in the feature's test folder with the builder's namespace and no `#if`; their text is otherwise
   upstream's.
3. **Docs** drop "On Jellyfin 12" and the sentence about 10.11: these pages describe a Jellyfin 12 plugin.
4. The ledger's guessed feature `hidden-content` (from the word in the test file's name) is corrected to
   `activity` alone.

Kept from upstream as it is:

- A failing version or by-name lookup shows fewer rows instead of an error. Those rows were always hidden before
  the change, the failure is logged, and showing them without the access answer would be the worse fault. The
  page's own access query still fails the request as before.
- When a shown `Watched` row is partial, the unread watches of its author go through the same access queries, 64
  at a time. `activity.json` holds at most 500 entries, so this is at most eight more rounds per request.

No found bug was filed against upstream's commit.

## 5. Risk, for the reviewer

- **Access, privacy, spoilers.** This is the part to read. The feed shows rows it did not show before, so each
  new row must be one the viewer may see. Every new row passes a query that Jellyfin scopes for the viewer
  (library roots, parental and tag rules): the version itself with `IncludeOwnedItems`, the title on the card
  with the ordinary query, a by-name favorite with Jellyfin's by-name rule, and only when the item has no
  library. Turning off the grouping by presentation key drops no access filter: grouping runs after them. Tests:
  no row and no item load for a viewer without the version's library, with the version or the title blocked by
  parental rules, for a folder artist of a library the viewer lacks, for a `Watched` entry naming a person. Lab:
  the restricted users' rows match Jellyfin's own answers (section 3). What a viewer can newly learn is that
  someone played or favorited a title, person, genre or studio the viewer can already open.

  log (kept from upstream, section 2). The feed's own access query still fails the request.
- **Requests to other hosts:** none. **Stored data:** unchanged; `activity.json` keeps the id that was played

- **Cost.** A page of candidates makes one access query as before, one more when it holds a denied id, and one
