## 2. The entries

Each entry's ledger `notes` say where the code went and every difference from upstream; this is the short form.

### 64. Maintainerr: the version picked on the item page picks the collection

`MaintainerrActionRequest` gains `mediaSourceId`; `MarkAsync` finds that version among the movie's media sources and,
when one library has a manual collection per Radarr (a 4K and a 1080p list), counts a Radarr as holding the movie only
when one of its movies has a file of the version's file name (`FileMatchesVersion`, true when either side has no file
name). Without a version, with an unknown one or for a series, the match is as before. The item menu sends the value
of the detail page's version picker, read when the row is pressed. Differences from upstream: only the detail page's
own ⋮ sends it (upstream also sent the page's version from a More like this card's ⋮, for another item; the server
then ignored it); Keep's Undo, which marks again, sends it too (upstream's Undo after Keep was refused as "more than
one Radarr/Sonarr server has it" on such a library); the docs describe the field and the rule.

### 65. Maintainerr: seasons in the item menu

`MediaType` answers `season`, so a season's card and page get Mark, Keep and Postpone; several season collections
on one library are told apart by asking each Sonarr for the season's series by its TVDB id; the refusals name
"movies, series and seasons". Maintainerr gets what upstream sends (the season's id as `mediaId` and context id,
context type `season`). Episodes still get no rows. Difference from upstream: the docs (`tags.md` said "Seasons and
episodes get no rows"; `api.md`'s Supported, refusal and probe).
